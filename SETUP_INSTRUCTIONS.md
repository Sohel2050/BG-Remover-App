# Setup Instructions — Full App (Parts 1-10)

This zip contains all Dart source code + config additions for the
complete app. It does NOT contain the full native Android/iOS scaffold
(thousands of files generated by the Flutter SDK, not available in the
sandbox this was built in) — you'll generate that with `flutter create`
and layer this code on top.

## Steps

1. Create a fresh Flutter project with the app's package name
   (`com.albonik.bgremover`) set from the start:
   ```bash
   flutter create --org com.albonik --project-name bgremover bg_remover_app
   cd bg_remover_app
   ```
   `--org com.albonik` + `--project-name bgremover` makes `flutter create`
   generate `applicationId "com.albonik.bgremover"` and the matching
   `MainActivity.kt` package path itself — so you may not even need step
   3's manual edits below. If you'd rather reuse an existing project
   instead of creating a new one, apply this zip's
   `android/app/src/main/kotlin/com/albonik/bgremover/MainActivity.kt` and
   the namespace/applicationId lines in step 3 by hand, and delete any
   leftover `android/app/src/main/kotlin/.../MainActivity.kt` under the
   old package path (e.g. `com/example/...`) so there isn't a duplicate.

2. From this zip, copy over (overwrite):
   - `pubspec.yaml`
   - the entire `lib/` folder
   - the entire `assets/` folder

3. Apply native config:
   - **Android**: in `android/app/build.gradle.kts`, set `namespace =
     "com.albonik.bgremover"`, `applicationId = "com.albonik.bgremover"`,
     `minSdk = 24`, `compileSdk = 36`, `targetSdk = 34` (see
     `android/app/build-gradle-snippet.txt` in this zip — if you used
     `--org`/`--project-name` in step 1, these are likely already
     correct; just double-check). Replace your generated
     `android/app/src/main/AndroidManifest.xml` with the one in this zip
     (already has camera/gallery permissions).
   - **iOS**: open `ios/Runner/Info.plist` and add the keys shown in
     `ios/Runner/Info-permissions-snippet.plist` (camera, photo library
     read, photo library add — the last one is needed by the `gal`
     package for saving to the gallery in Part 7).

4. Get the AI model (Part 2) — **required, not bundled** (binary, too
   large to hand-write): see `assets/models/MODEL_SETUP.md` for where to
   download `u2net.onnx` (or the lighter `u2netp.onnx`) and where to put
   it.

   **Note:** AI inference uses the `flutter_onnxruntime` package (not the
   older, unmaintained `onnxruntime` package — that one is stuck on an
   old Android `compileSdk` and fails to build against modern androidx
   dependencies). Two things this package needs that are already set up
   in this zip:
   - `android/app/proguard-rules.pro` with `-keep class ai.onnxruntime.** { *; }`
   - `android/app/build.gradle.kts` → `compileSdk = 36` (see
     `build-gradle-snippet.txt`)

   If you build for iOS, this package requires **iOS 16+** and static
   linkage — in `ios/Podfile`, set `platform :ios, '16.0'` and
   `use_frameworks! :linkage => :static`.

   **iOS bundle identifier:** using `--org com.albonik --project-name
   bgremover` in step 1 also sets this to `com.albonik.bgremover`
   automatically. To change it later on an existing project, open
   `ios/Runner.xcodeproj` in Xcode → Runner target → General →
   "Bundle Identifier" (there's no plain-text file for this — it's
   stored inside the Xcode project file).

   **Also fixed:** `share_plus` was originally pinned to an old version
   (7.2.2) that hit the same "compiled against android-33" build error.
   It's now `^13.3.0`, and `export_screen.dart` uses that version's
   current API (`SharePlus.instance.share(ShareParams(...))` instead of
   the deprecated `Share.shareXFiles(...)`).

5. Install dependencies:
   ```bash
   flutter pub get
   ```

6. Run:
   ```bash
   flutter run
   ```

## Full app flow
```
Home
 ├─ Choose from Gallery / Take a Photo → Edit
 │     Edit: AI remove → brush erase/restore (pinch zoom/pan,
 │           undo/redo, edge softness) → background picker
 │           (transparent/solid/blur/custom) → Compare (before/after)
 │           → Export
 │               → Refine (rotate, social/ID-photo size presets,
 │                 brightness/contrast, auto-enhance, drop shadow,
 │                 sticker outline, text-behind-subject)
 │               → Export screen (Save to Gallery / Share)
 ├─ Batch Process Multiple Images (auto-remove only, save all)
 ├─ Collage Maker (combine 2-6 processed images into a grid)
 ├─ Recent Projects (thumbnail history)
 └─ Settings (theme: system/light/dark)

First launch → 3-page Onboarding intro before Home.
```

## Ads (Unity LevelPlay mediation)
Monetization via Unity LevelPlay, mediating 13 networks (Chartboost, Meta
Audience Network, InMobi, Mintegral, MobileFuse, Moloco, Ogury, PubMatic,
Smaato, Unity Ads, Verve, Yandex, Vungle, AppLovin).

**App key & ad unit IDs** are in `lib/services/ads_service.dart`
(`AdIds` class) — already filled in with the ones you gave:
App key `2820a4965`, Banner `4cafh3jwdbyn6ohp`, Interstitial
`hu149fj6h72r1ebj`, Native `ypo41rpcpf7pvcnq`, Rewarded `mn5ikgnzdo1xdlgh`.

**Where each ad shows:**
- **Banner** — bottom of the Home screen
- **Interstitial** — once when the Export screen opens (after a photo is
  fully edited, not mid-task)
- **Rewarded** — a "Support this free app" button in Settings
- **Native** — one card in the AI Tools list

**Android setup (do all of this):**
1. Add every dependency in `android/app/levelplay-adapters-snippet.txt`
   to your `android/app/build.gradle.kts` `dependencies { }` block (the
   LevelPlay core SDK itself comes bundled in the Flutter plugin — these
   are just the per-network adapters + their own ad SDKs, plus the three
   Play Services libs the plugin requires).
2. `AndroidManifest.xml` in this zip already has `INTERNET`,
   `ACCESS_NETWORK_STATE`, and the `AD_ID` permission the ad SDKs need on
   Android 13+.
3. `android/app/proguard-rules.pro` in this zip already has keep rules
   for LevelPlay core + all 13 networks.

**⚠️ Realistic expectation:** this is 13 separate third-party SDKs, each
with its own `compileSdk`/`minSdk`/Kotlin-version requirements — exactly
the class of error you hit earlier with `flutter_onnxruntime` and
`share_plus` (AAR metadata mismatches). It's very likely at least one of
these pinned versions will throw a similar "compiled against android-XX"
error on first build. If/when that happens: send the exact error, and
the fix is the same pattern as before — bump that one network's adapter/
SDK version pair to whatever's current on Maven Central.

**iOS setup:**
1. Add every pod in `ios/levelplay-podfile-snippet.rb` to your
   `ios/Podfile`'s `target 'Runner' do ... end` block. Each adapter pod
   pulls in its own network's SDK automatically (unlike Android, you
   don't separately add the raw SDK pods).
2. Add the keys in `ios/levelplay-info-plist-snippet.plist` to
   `ios/Runner/Info.plist` (ATT usage description, App Transport
   Security, and a partial SKAdNetworkItems list).
3. **You still need to fill in ~8 more SKAdNetwork IDs** — only
   LevelPlay/AppLovin/Chartboost/Meta/Mintegral's IDs were independently
   confirmed; InMobi, MobileFuse, Moloco, Ogury, PubMatic, Smaato, Unity
   Ads, Verve, Yandex, and Vungle are NOT included (a wrong/guessed ID
   silently breaks that network's attribution, which is worse than
   leaving it for you to fill in correctly). Get the complete, correct
   list from Unity's official generator:
   https://docs.unity.com/en-us/grow/levelplay/sdk/ios/add-skadnetwork-ids-manually
4. Adapter version numbers for iOS were assumed to match the Android
   ones you gave (confirmed true for AppLovin 5.9.0 existing on both
   platforms) — if `pod install` can't resolve one, check
   `https://cocoapods.org/pods/IronSource<Name>Adapter` for the closest
   available version.

**Not compiled/tested** — like the AI Tools, this was written without a
Flutter SDK available to build against. The Dart API calls
(`LevelPlayInitRequest`, `LevelPlayInterstitialAd`, etc.) match the
plugin's own README examples, but send the exact error if something
doesn't match the installed plugin version's actual API.

## Release build signing (Play Store)
`build.gradle.kts` currently signs release builds with the **debug**
key, which the Play Store will reject. See
`android/RELEASE_SIGNING_SETUP.md` for the full walkthrough — generating
a keystore, filling in `android/key.properties` (template:
`android/key.properties.example`), and the exact `build.gradle.kts`
changes to wire it up. Do this before your first `flutter build
appbundle --release`.

## Force/optional update check (GitHub-hosted config)
On startup the app fetches:
```
https://raw.githubusercontent.com/Sohel2050/Background-Remover-Controller/main/update_config.json
```
(the **raw** file — a GitHub "blob" page link is HTML, not usable
directly) and compares the installed version (from `pubspec.yaml`'s
`version:` line, read via `package_info_plus`) against it:
- installed < `min_version` → **forced** update (non-dismissible dialog,
  back button blocked, only "Update Now")
- installed < `latest_version` (but ≥ `min_version`) → **optional**
  prompt (has a "Later" button)
- network/parse failure → silently skipped, app opens normally

The app's package (`com.albonik.bgremover`) now matches the repo's
`play_store_url` (`id=com.albonik.bgremover`). Still fill in the real
`app_store_url` before shipping to iOS (it's currently a placeholder
`idXXXXXXXXX`).

To push a forced update later: edit `update_config.json` in that repo,
bump `min_version` to your new release's version, commit — every
installed app picks it up on next launch, no app update needed for the
check itself.

## AI Tools screen (Object Removal, Upscale 4x, Select Subjects, Skin Smoothing)
A new "AI Tools" entry on Home opens four extra tools:
- **Object Removal** (LaMa inpainting) and **Upscale 4x** (Real-ESRGAN)
  and **Select Subjects** (YOLOv8n-seg) each need their own model file —
  see `assets/models/MODELS_SETUP.md` for exact download links/commands.
- **Skin Smoothing** needs no model — it's a color-based blur, works
  immediately.
None of this code has been compiled (written in a sandbox without the
Flutter SDK) — run it and send the exact error if something doesn't
build; the model I/O contracts (shapes, value ranges) were verified
against each model's published documentation, but small mismatches
between model export variants can still surface as a shape-mismatch
exception at runtime, which the tools will show in a SnackBar.

## Known limitations (documented on purpose, not bugs to "fix")
- **Recent Projects** are stored in permanent app storage
  (`projects/` in the app documents directory). Tap to reopen with brush
  strokes restored; long-press to delete. Exports (Refine/Export
  screens) still use temp files — save them to the gallery to keep them.
- **Sky Replacement** and **Multiple Subject Detection** are NOT
  implemented — see `NOTES_SKY_AND_MULTISUBJECT.md` for why (they need
  a separate specialized model each, not an extension of the single-mask
  U2Net pipeline already built).
- All AI inference is on-device via `onnxruntime` — no server, no API
  cost, works offline.

## Suggested build order if you want to verify incrementally
Even though this is delivered as one zip, the code is structured so you
can sanity-check it in the same order it was built:
1. `flutter run` → Home → pick an image → confirm Edit screen shows it
2. Tap "Remove Background" → confirm AI result renders (needs the model
   file from step 4 above)
3. Try brush erase/restore, pinch zoom, undo/redo
4. Try background picker + Compare toggle
5. Export → Refine (try a rotate, a preset, a filter) → Export screen →
   Save/Share
6. Try Batch Process and Collage Maker from Home
7. Check Settings (dark mode) and Recent Projects
